# personal-tracker-v2 要件定義書

## 1. 背景と目的

本プロジェクトは、外部サーバーに依存しないローカルファーストの健康管理アプリケーションです。

### 主要な特徴
- **オフライン完結**: 各端末にデータを保存し、ネット接続不要
- **マルチプラットフォーム**: Desktop / Android / Web（+ iOS 任意）を単一コードベースで対応
- **ローカルDB**: SQLite による永続化
- **データ主権**: バックアップ/リストアで完全なデータ管理

### 実装する機能
1. カテゴリ、タグ、トラック、日記、分析の各機能
2. Flutter による統一されたUI/UX
3. SQLiteバックアップ/リストアとJSONエクスポート/インポート

## 2. 用語
- **カテゴリ (category)**: 記録を分類する上位概念。色付きで表示。
- **タグ (tag)**: カテゴリに属する細分化されたラベル。トラックに紐付けられる。
- **トラック (track)**: 時系列の出来事ログ。メモ・コンディション（-2〜2）・複数タグを持つ。
- **日記 (daily)**: 1 日 1 件の詳細な記録。メモ・睡眠・コンディションを保持。
- **分析 (analysis)**: トラック／日記データを集計し、統計や傾向を表示する機能群。

## 3. 対象プラットフォーム
- **必須**: Web（ブラウザ版）、macOS / Windows / Linux デスクトップ、Android
- **任意（将来対応）**: iOS
- 各プラットフォームで共通のソースコードを維持し、UI レイアウトは各デバイスサイズに応じて調整する。

## 4. データ永続化要件
- SQLite を正とする。Web では sqlite3_wasm + IndexedDB/OPFS を利用し、モバイル/デスクトップはネイティブ SQLite を使用する。
- Drift ORM を使用してスキーマとクエリを管理する。

### 4.1 テーブル仕様

本プロジェクトでは以下の4つのテーブルを使用します：

- **Category**: カテゴリ情報（薬、症状、食事など）
- **Tag**: タグ情報（デパス、頭痛など）
- **Track**: 日々の記録（メモ、コンディション、タグ）
- **Daily**: 日記（1日1件）

詳細なスキーマ定義（フィールド、型、制約）は **[schema.md](schema.md)** を参照してください。

**Drift実装時の注意点:**
- UUID は TEXT 型で保存し、UUID v7 を使用（`uuid` パッケージ ^4.5.1）
- `tag_ids` は JSON 文字列として保存
- 日時は UTC で保存し、表示時に JST 変換
- `updated_at` はアプリ側で更新時に自動設定

**UUID v7 実装例:**
```dart
import 'package:uuid/uuid.dart';
const uuid = Uuid();
String id = uuid.v7(); // 時刻ベース、ソート可能なID生成
```

### 4.2 タイムゾーン方針
- DB は UTC 保管、表示・集計は JST 基準
- Dart の `timezone` パッケージを使用して JST 変換を実装
- 日付境界は JST 基準（例: `2025-10-23` は JST の0:00〜23:59を指す）

### 4.3 バックアップ / エクスポート

**注: この機能は Phase 8（オプション）として、コア機能完成後に実装予定**

#### バックアップ/リストア（SQLiteファイル）
- **用途**: 完全バックアップ・デバイス移行・災害復旧
- **方式**: SQLiteファイルを丸ごとコピー
- **リストア**: 既存データを完全上書き（事前に警告ダイアログ表示）
- **ファイル名例**: `personal-tracker-backup-20251023.db`

#### エクスポート/インポート（JSON形式）
- **用途**: データ移行・手動編集・複数デバイス間のマージ
- **方式**: 全テーブルをJSON形式で出力
- **インポート時の挙動**: `updatedAt` を比較し、新しい方を採用（マージ処理）
- **ファイル名例**: `personal-tracker-export-20251023.json`

#### 共通仕様
- OS 標準のファイルピッカーを利用（Web版は `file_picker` パッケージ）
- 手動操作のみ（自動バックアップは将来検討）
- エクスポート前に確認ダイアログを表示

## 5. 機能要件

### 5.1 共通
- 起動時に SQLite を初期化し、必要なマイグレーションを即時適用する
- 全データ操作はリポジトリ層を経由し、状態管理（Riverpod）へストリーム配信する
- UI からの入力バリデーションは独自ロジックで実装し、日本語のエラーメッセージを統一する
- バリデーション詳細は **[validation.md](validation.md)** を参照

### 5.2 カテゴリ管理
- 一覧表示（アーカイブ有無のフィルタ付き）
- 追加（`sortOrder` 自動採番、8色のカラーパレットから選択）
- 編集（名称・色・アーカイブ状態）
- 並び替え（連番制約を維持）

### 5.3 タグ管理
- カテゴリごとの一覧、アーカイブ切替
- 作成・編集（名称のみ）・並び替え
- カテゴリ削除時に紐づくタグは連鎖削除
- **タグ削除**: アーカイブ画面でのみ実行可能。削除時は全Trackから該当タグIDを即座にクリーンアップ
- **アーカイブUI**: 画面左下の「Archived」リンクから専用画面に遷移
- UI 詳細は **[ui_behavior.md](ui_behavior.md)** を参照

### 5.4 トラック
- 上方向への無限スクロール（過去を遡る）
- メモ / コンディション / タグ / **記録日時**の CRUD
- **記録日時の編集**: 過去の出来事を後から記録できるよう、記録日時（`recordedAt`）を手動設定可能
- タグはカテゴリ色付きチップで表示
- 検索（文字列 & タグ & コンディション）フィルター（左サイドバーに配置）
- レコード削除

### 5.5 日記
- カレンダー / リスト表示切替
- 任意日付での記入（1日1件）・編集
- コンディション・睡眠時間の入力（時刻ピッカー）
- コンディションフィルター

### 5.6 分析
- **コンディション推移**: 期間選択UI（1d/1w/1m）で積み上げ棒グラフ表示
  - **1d（日単位）**: Trackのコンディションを日別に集計（1日の変化を可視化）
  - **1w/1m（週/月単位）**: Dailyのコンディションを集計（1日の総括評価）
- 日次集計: 平均/最小/最大/件数/睡眠時間
- 睡眠分析: 縦棒（就寝〜起床の範囲）+ 折れ線（睡眠時間）の複合グラフ
- タグ影響ベイズ推定: タグの翌日以降コンディションへの寄与度を算出
- グラフ描画は `fl_chart` パッケージを使用

### 5.7 設定
- テーマ切替（ライト/ダーク）、SharedPreferencesで永続化
- ログ出力レベル設定（開発: debug、本番: warning）
- バックアップ/リストア UI（Phase 8で実装予定）

## 6. 非機能要件
- **パフォーマンス**: 1万件のトラックでも滑らかにスクロール。`ListView.builder` で仮想化を徹底
- **オフライン**: ネット接続不要。外部APIなし
- **セキュリティ**: 端末ローカル保存。将来的にデータ暗号化の拡張ポイントを設ける
- **可観測性**: `logger` パッケージでログを統一し、開発ビルドでは devtools へ出力

## 7. アーキテクチャ指針
- **レイヤー構成**: presentation（Widget + ViewModel） / application（UseCase） / domain（モデル） / infrastructure（DB, Platform）
- **状態管理**: Riverpod + StateNotifier。StreamProvider で DB の変更を購読
- **DB アクセス**: Drift の DAO / Queries を use case から呼び出す。マイグレーションは Migrator で管理
  - `sortOrder` の自動採番はトランザクション内で実行（`max(sortOrder) + 1`）
- **日付処理**: `intl` と `timezone` パッケージで JST 基準を実現
- **DI**: Riverpod Provider で共通依存を注入
- **ルーティング**: GoRouter で画面遷移を定義。Web / モバイル共通 URL 設計
- **統計計算**: `dart:math` と `statistics ^1.2.0` パッケージで平均・分散・標準偏差を計算

### 7.1 ベイズ推定実装方針

タグ影響分析のベイズ推定は、**Normal-Normal共役事前分布**を使用して自前実装する。

**使用パッケージ:**
- `dart:math`: sqrt, pow などの数学関数
- `statistics ^1.2.0`: 平均・標準偏差の計算

**計算式（Normal-Normal共役）:**
```
事後平均 = (事前平均 × 仮想サンプル数 + 観測平均 × 観測数) / (仮想サンプル数 + 観測数)
事後分散 = 事前分散 / (仮想サンプル数 + 観測数)
95%信用区間 = 事後平均 ± 1.96 × √事後分散
```

**デフォルトパラメータ:**
- 事前平均: 0（タグの影響なしを仮定）
- 事前分散: 1
- 仮想サンプル数: 5（事前情報の強さ）

**実装場所:**
- `lib/domain/services/bayesian_estimator.dart` にユーティリティクラスとして実装
- ユニットテストで数値精度を検証

**参考実装:** ui_behavior.md:269-316 のロジックに基づく

## 9. テスト戦略
- **ユニットテスト**: UseCase / Repository / Converter
- **ウィジェットテスト**: トラック一覧、日記フォーム、グラフ描画
- **Integration Test**: 主要ユーザーフロー（トラック作成→タグ付与→分析表示）
- **Golden Test**: 代表画面のレイアウトをゴールデン化し、プラットフォーム差異を検出

## 10. 開発プロセス（推奨フェーズ）
1. **Phase 0**: Flutter プロジェクト初期化、Drift/Freezed セットアップ
2. **Phase 1**: データ層（スキーマ・マイグレーション）の実装とテスト
3. **Phase 2**: カテゴリ/タグ UI + 状態管理
4. **Phase 3**: トラック UI・無限スクロール・フィルター
5. **Phase 4**: 日記 UI（カレンダー含む）
6. **Phase 5**: 分析（コンディション集計,睡眠分析,タグ影響ベイズ推定）
7. **Phase 6**: 設定画面（テーマ切替、ログ設定）
8. **Phase 7**: E2E / Integration テスト、アプリ配布準備
9. **Phase 8（オプション）**: バックアップ/リストア機能（SQLite + JSON両対応）

## 11. リスクとオープン課題
- タグ相関分析のベイズ推定で、データ量が少ない場合の数値安定化が必要
  - 観測数が3件未満の場合は「データ不足」として表示を抑制
  - 事前分布のパラメータ調整で過学習を防止
- Web 版の sqlite3_wasm はブラウザ互換性の検証が必要（特に Safari）
- iOS 対応を行う場合、App Sandbox 設定とファイル保存先を追加設計

### 将来的な拡張ポイント
- **タグ相互作用の分析**: 現在は各タグの単独効果のみ評価。複数タグの組み合わせ効果（相乗・相殺）を分析する場合、ベイジアンネットワークの導入を検討
- **因果推論の高度化**: 直接効果と間接効果の分離（例: カフェイン→睡眠→コンディション）
- **反事実推論**: 「もしこのタグを使わなかったら」のWhat-if分析
